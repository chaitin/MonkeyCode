# 移动端顶部任务工具与消息定位底部操作设计

## 背景

当前未提交实现将手机端模型入口改为品牌图标、模型名称和上下文进度组成的组合控件，并将更多任务工具放入底部 Drawer。该结构改变了原有模型入口的视觉层级；底部 Drawer 与随后打开的文件、技能、预览和发布浮层也容易在关闭动画、遮罩与焦点恢复期间产生重影。

现有 `TaskUserInputIndex` 已分别提供桌面端圆点定位栏和手机端定位 Drawer。该官方消息定位交互继续作为唯一实现。本轮只增加“回到底部”能力，并确保手机端定位入口处于页头正常布局中，不遮挡消息内容，不与模型、上下文或更多入口重叠。

## 目标

1. 手机端模型入口恢复改版前的独立视觉和信息层级。
2. 手机端更多任务工具从任务页头下方向下展开。
3. 手机端更多工具与文件浏览器使用同一个顶部面板实例。
4. 官方消息定位的入口、圆点栏、Drawer、列表、分页和消息跳转保持现状。
5. 官方消息定位内容底部增加“回到底部”按钮，并仅在消息区离开底部时显示。
6. 320px 及以上手机宽度不出现页头控件重叠、消息遮挡或页面级横向滚动。
7. 桌面端模型、任务工具、文件侧栏和消息定位布局保持现状。

## 方案选择

### 方案 A：单一页头下方 Popover

手机端更多工具使用页头下方的 Popover。工具网格与文件浏览器通过面板内部模式切换，共享一个 Portal、一个焦点范围和一段开合动画。

优点：

- 紧贴触发入口，方向符合顶部展开预期
- 文件切换不创建第二层遮罩
- Radix 继续处理 Escape、点击外部和焦点恢复
- 改动集中在任务页手机端分支

### 方案 B：顶部 Sheet

使用 `Sheet side="top"` 承载更多工具和文件。

代价：

- 现有 Sheet 从视口顶端进入，需要额外处理应用栏与任务页头偏移
- 全屏遮罩和模态语义高于本场景需要

### 方案 C：页头内联展开区

在任务页头下方插入工具或文件内容，并推动消息区下移。

代价：

- 开合会改变消息区高度和滚动位置
- 文件内容展开时页面布局波动明显

采用方案 A。

## 手机端页头

断点保持小于 768px。页头使用单行 flex 布局，所有入口位于正常文档流中：

1. 模型与上下文区域使用 `min-width: 0` 和 `flex: 1`，承担窄屏收缩。
2. 官方消息定位入口保持 `TaskUserInputIndex` 当前 44px 按钮和现有图标。
3. 更多入口保持独立 44px 按钮。
4. 定位与更多入口使用 `shrink-0`，不进入消息内容区，不使用绝对定位。
5. 320px 宽度下，模型名称在按钮内部省略，定位与更多入口保持完整可见。

### 模型入口

恢复改版前的独立结构：

- 模型按钮独立显示模型名称和下拉箭头。
- 移除手机端新增的品牌图标。
- 移除模型与上下文共享的组合边框。
- 上下文进度恢复为独立入口。
- 模型选项、分组、权限、切换确认和错误处理逻辑保持现状。
- 手机端保留至少 44px 的点击高度，视觉层级、边框和字体沿用旧入口。

## 手机端更多任务工具

底部 Drawer 替换为受控 Popover。Popover 固定从触发按钮下方展开，向页头下方延伸：

- 使用 `side="bottom"`、`align="end"` 并关闭方向翻转，固定从页头下方向下展开。
- 宽度限制在手机视口内，左右保留安全边距。
- 最大高度约为 `65dvh`，超出内容在面板内部滚动。
- 使用现有 Popover 的向下进入和向上退出动画。
- 标题、说明、关闭按钮和工具禁用条件保持明确。
- Popover 使用模态交互边界；打开时背景中的消息定位入口不可操作，关闭后才能打开定位 Drawer。
- 官方定位 Drawer 打开时继续由现有模态边界阻止背景中的更多入口操作。

工具网格保留技能、文件、预览和条件发布：

- 技能、预览和发布先关闭 Popover，关闭动画结束后再打开目标 Dialog。
- 文件在同一个 Popover 内把内容模式从 `tools` 切换为 `files`。
- 文件模式直接复用 `TaskFileExplorer`，不同时打开右侧 `ResizablePanel`。
- 文件面板关闭时整个 Popover 向上收起。
- 下一次打开更多入口时恢复工具网格模式。

桌面端继续使用现有直接工具按钮和右侧文件面板。

## 官方消息定位与回到底部

`TaskUserInputIndex` 当前结构保持不变：

- 手机端继续使用现有按钮和底部 Drawer。
- 桌面端继续使用现有圆点栏、hover 展开和 280px 面板。
- `renderEntries`、分页加载、当前消息识别、跳转、高亮和错误提示保持现状。

组件新增两个输入：

- `isAtBottom: boolean`：表示消息区当前是否位于底部阈值内。
- `scrollToBottom: () => void`：由任务页提供现有平滑滚动能力。

当 `isAtBottom` 为 `false` 时，在官方定位内容底部渲染“回到底部”：

- 手机端按钮高度至少 44px，位于定位 Drawer 的列表下方；点击后平滑滚动到底部并关闭 Drawer。
- 桌面端按钮位于现有 hover 面板列表下方；点击后平滑滚动到底部。
- 到达底部阈值后按钮隐藏，不保留空白 footer。
- 按钮不参与消息索引条目，不改变加载更多和定位中的 sticky 区域。

## 滚动状态

任务页现有 `updateChatScrollState` 已按 24px 阈值计算 `isAtBottom`。本轮把该结果同步到 React state，并继续维护现有自动滚动 ref：

1. 用户滚动、消息区尺寸变化或消息更新时刷新底部状态。
2. 状态值未变化时不触发额外渲染。
3. “回到底部”调用现有 `scheduleChatScrollToBottom("smooth", { forceAutoScroll: true })`。
4. 平滑滚动结束后，现有滚动监听把状态更新为已到底部并隐藏按钮。

不新增第二套滚动判断，不修改虚拟消息列表接口。

## 浮层互斥与重影控制

手机端通过现有模态交互边界保证同一时刻只有一个任务级浮层可操作：

- 更多工具 Popover 打开时，背景入口不可操作；点击外部先完成 Popover 关闭。
- 官方消息定位 Drawer 打开时，背景入口继续不可操作。
- 文件模式属于更多 Popover 内部状态，不创建新 Portal。
- 技能、预览和发布通过待执行动作在 Popover 退出动画后触发。
- 关闭过程中不立即切换文件与工具内容，避免退出帧内容闪烁。

## 可访问性

- 模型、上下文、消息定位、更多和回到底部均有独立可访问名称。
- 手机端所有常驻入口与新增按钮点击目标至少 44px。
- Popover 和官方定位 Drawer 均支持 Escape、点击外部与焦点恢复。
- 回到底部隐藏时从可访问树中移除。
- 文件模式保留 `TaskFileExplorer` 当前键盘和按钮语义。

## 边界情况

- 消息内容没有滚动溢出时视为已到底部，不显示按钮。
- 滚动位置距底部不超过 24px 时视为已到底部。
- 消息区尚未挂载时维持已到底部默认值。
- 长模型名在 320px 页头内省略，定位和更多按钮不得收缩。
- 消息索引为空或仅有一个条目时，官方定位组件继续按现有规则不渲染；回到底部不单独创建定位入口。
- 文件环境未就绪、文件加载失败和禁用状态继续使用 `TaskFileExplorer` 当前处理。
- 横竖屏切换继续只挂载一个消息定位呈现实例。

## 测试设计

### 自动测试

1. 验证手机端模型入口恢复独立结构，移除品牌图标和组合边框。
2. 验证 320px 布局使用可收缩模型区域与固定 44px 定位、更多入口。
3. 验证更多工具使用顶部 Popover，并具有向下展开方向和视口宽度约束。
4. 验证工具与文件使用同一个 Popover 实例，手机端文件不打开右侧面板。
5. 验证技能、预览和发布在 Popover 关闭动画后执行。
6. 验证官方消息定位现有手机与桌面结构未被替换。
7. 验证离开底部时两种定位呈现均显示“回到底部”，到底部时隐藏。
8. 验证手机点击回到底部后关闭官方定位 Drawer，桌面点击后保持现有 hover 行为。
9. 验证定位与更多手机浮层通过模态交互边界保持单实例可操作。
10. 运行聚焦 Node.js 测试、frontend ESLint、TypeScript 和 online build。

### 人工验收

使用 online 预览验证 320px、375px、390px、430px 和 1280px：

- 手机页头长短模型名均无重叠和横向滚动
- 官方定位按钮不遮挡消息内容
- 官方定位 Drawer、圆点栏、hover 面板和跳转行为保持现状
- 离开底部后按钮出现，点击后平滑回到底部并隐藏
- 更多工具从页头下方展开和向上收起
- 文件在同一顶部面板内打开和关闭
- 快速交替点击定位、更多、文件、技能和预览时无双遮罩、重影或焦点跳动
- 桌面工具栏、文件侧栏和消息区布局保持现状

## 非目标

- 不重设计官方消息定位组件。
- 不修改消息索引 API、分页协议或虚拟消息列表接口。
- 不改变桌面端文件侧栏和任务工具布局。
- 不新增全局状态或第三方依赖。
