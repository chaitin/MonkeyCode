# Web 任务页移动端顶部工具区布局设计

## 背景

Web 任务详情页顶部工具区同时展示模型选择、上下文使用率、技能、文件、预览和发布操作。当前结构将左右两组控件放在同一条不可换行的 flex 行中，并为模型按钮和右侧操作组保留收缩约束。

手机宽度下，所有控件的总宽度超过可用空间，模型名称、技能按钮和文件按钮相互挤压，形成文字截断、视觉碰撞和触控边界不清的问题。

## 目标

1. 320px 及以上宽度下，顶部所有可见控件互不重叠。
2. 手机端保留模型、上下文、技能、文件、预览和发布的可见名称与直接入口。
3. 手机端交互控件触控高度至少为 44px。
4. 手机端工具区不产生页面级横向滚动。
5. 768px 及以上宽度保持现有桌面端单行布局、尺寸、文案和交互。

## 方案比较

### 方案 A：上下分两行

手机端第一行展示模型与上下文，第二行展示技能、文件、预览和发布。第二行操作按实际数量等宽分布。

优点：

- 所有操作保留图标和文字，识别成本低
- 每个触控目标拥有稳定宽度和高度
- 模型名称获得充足的自适应空间
- 权限或状态引起操作数量变化时可以自动均分

代价：

- 顶部工具区高度增加约 42px

### 方案 B：单行图标化

手机端所有控件维持一行，技能、文件、预览和发布仅显示图标。

优点：

- 工具区高度最小
- 内容区获得更多垂直空间

代价：

- 图标含义需要用户记忆
- 模型名称可用宽度仍然有限
- 320px 宽度难以同时容纳六个 44px 触控目标

### 方案 C：更多菜单收纳

手机端保留部分高频操作，将其余操作收进更多菜单。

优点：

- 顶部空间紧凑
- 高频操作可以保持文字标签

代价：

- 被收纳操作增加一次点击
- 需要新增菜单结构、焦点管理和状态反馈
- 文件、预览和发布的使用频率会因任务阶段变化

采用方案 A。

## 布局设计

### 手机端

断点范围为小于 768px。

顶部容器改为纵向排列，两行宽度均占满可用空间：

1. 第一行使用 flex 布局。
2. 模型按钮使用 `min-width: 0` 和 `flex: 1`，名称超宽时显示省略号。
3. 上下文按钮保持 44px × 44px 的固定触控区，内部继续使用现有圆形进度组件。
4. 第二行使用按列自动均分的 grid 布局。
5. 技能、文件、预览和发布按钮高度均为 44px，保留图标和短文案。
6. 第二行根据实际渲染的按钮数量自动均分宽度。
7. 手机端继续隐藏终端按钮，维持现有功能范围。

发布按钮继续根据 `canPublishWebsite` 条件渲染。发布入口隐藏时，其余按钮自动占满第二行。

### 桌面端

断点范围为 768px 及以上。

顶部容器继续使用当前横向排列：

- 模型、上下文与操作组保持同一行
- 操作按钮继续使用现有 28px 高度和紧凑间距
- 终端按钮继续在现有断点显示
- 当前选中态、禁用态和点击行为保持原实现

## 组件边界

改动集中在 `frontend/src/pages/console/user/task/task-detail.tsx` 的 `detailHeader`：

- 不拆分新的业务组件
- 不改变模型切换、上下文管理、面板切换或发布状态
- 不改变按钮渲染条件和事件处理函数
- 通过响应式 class 调整现有 DOM 的排列、尺寸和宽度

该范围保证移动端和桌面端共享同一份业务状态与事件逻辑。

## 可访问性

- 所有手机端可见按钮保持图标与文字标签
- 模型按钮和上下文按钮保留现有可访问名称
- 手机端每个交互目标高度至少为 44px
- 键盘焦点顺序保持 DOM 顺序：模型、上下文、技能、终端、文件、预览、发布
- 按钮禁用态、焦点环和选中态继续沿用共享 Button 样式

## 边界状态

- 模型名称很长时仅模型文字区域省略，下拉图标和上下文按钮保持可见。
- 上下文数据暂不可用时，模型按钮占用第一行可用宽度。
- 发布入口不可用时，技能、文件和预览三列等宽排列。
- 文件变更计数和预览端口计数出现时，按钮文字保持单行并在列内受控截断。
- 320px 宽度下两行均位于视口内，页面不产生横向滚动。
- 中文和英文文案均使用相同响应式结构。

## 测试设计

### 自动测试

1. 新增任务详情页移动端页头布局测试。
2. 验证页头在手机端使用纵向排列，在 768px 及以上恢复横向排列。
3. 验证模型区域具备 `min-w-0` 和自适应宽度。
4. 验证上下文触控区和移动端操作按钮高度至少为 44px。
5. 验证手机端操作组按实际按钮数量等宽分布。
6. 验证桌面端按钮继续使用现有紧凑高度。
7. 运行相关测试、frontend ESLint、TypeScript 检查和 online build。

### 人工验收

使用 online 预览验证 320px、375px、390px、430px 和 1280px：

- 模型短名称与长名称
- 上下文数据存在和暂不可用
- 文件变更计数为零和非零
- 预览端口计数为零和非零
- 发布入口显示和隐藏
- 中文和英文界面
- 各按钮默认、选中、禁用和键盘聚焦状态

验收结果应满足：

- 控件和文字无重叠
- 所有可见操作均可准确触控
- 模型名称省略行为稳定
- 页面无横向滚动
- 桌面端布局与改动前一致
- 字体族、字号、字重和行高符合现有样式

## 范围边界

本次只调整 Web 任务详情页顶部工具区的响应式布局。输入栏、消息列表、模型切换逻辑、上下文操作逻辑、文件和预览面板、发布流程以及 React Native 页面保持原实现。
