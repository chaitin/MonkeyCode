# Web 任务页移动端紧凑工具栏与对话定位设计

> 状态：历史方案，已被 `2026-07-27-mobile-top-tools-and-scroll-bottom-design.md` 取代。最终实现保留单一右侧圆点定位面板，不使用手机定位 Drawer 或 `presentation` 分支。

## 背景

任务详情页顶部原有模型、上下文、技能、文件、预览和发布操作在手机宽度下发生挤压。第一轮修复采用上下两行布局，解决了控件重叠和触控空间问题，但仍保留桌面按钮的横向“图标 + 文字”结构，视觉密度较高。

消息区右侧的 `TaskUserInputIndex` 使用绝对定位常驻显示圆点栏。该圆点栏覆盖在消息内容上方，遮挡输出文字；其 hover 展开方式也缺少稳定的手机触控交互。

本设计取代 `2026-07-27-mobile-task-header-layout-design.md` 中的手机端两行方案。桌面端约束继续保持有效。

## 目标

1. 手机端顶部工具栏使用单行紧凑结构，320px 及以上宽度无控件碰撞和页面级横向滚动。
2. 当前模型按钮展示品牌图标、模型名称和下拉状态。
3. 上下文入口与模型入口形成统一视觉分组，同时保持独立语义和点击行为。
4. 手机端常驻操作仅保留模型组、定位和更多三个区域。
5. 定位与更多操作通过底部抽屉展示，所有触控目标至少为 44px。
6. 手机端消息内容使用完整可用宽度，不受定位栏覆盖。
7. 768px 及以上保持现有桌面页头、圆点定位栏和交互行为。

## 方案比较

### 方案 A：模型组合条与五项图标 Dock

模型和上下文组成第一行，定位、技能、文件、预览和发布组成第二行纵向图标 Dock。

优点：

- 所有操作保持直接可见
- 图标与文字纵向排列后横向空间稳定
- 信息层级清楚

代价：

- 常驻入口仍有六个
- 顶部继续占用两行高度

### 方案 B：模型组合条、定位与更多

手机端只保留模型组合条、定位按钮和更多按钮。定位和更多分别打开底部抽屉。

优点：

- 常驻入口减少为三个区域
- 顶部高度压缩为单行
- 定位入口离开消息内容区
- 底部抽屉提供充足的触控和文字空间

代价：

- 技能、文件、预览和发布增加一次点击

### 方案 C：可展开任务工具条

模型组合条独占第一行，第二行使用一个可展开工具入口。

优点：

- 收起时视觉简洁
- 展开状态可保留全部操作

代价：

- 展开状态改变页面高度
- 工具条开合会推动消息区位置

采用方案 B。

## 手机端页头设计

断点范围为小于 768px。

页头使用单行 flex 布局：

1. 左侧模型组使用 `min-width: 0` 和 `flex: 1`。
2. 右侧定位与更多按钮均为 44px × 44px，并使用 `shrink-0`。
3. 三个区域之间使用 8px 间距。
4. 320px 宽度下，模型名称在组内省略，图标、上下文、定位和更多入口始终可见。

### 模型组合条

模型组合条由一个共享圆角边框容器承载两个独立按钮：

- 模型按钮占用剩余宽度，包含当前模型品牌图标、名称和下拉箭头。
- 模型品牌图标复用 `Icon` 与 `getBrandFromModel(currentModel)`。
- 当前模型不可解析时隐藏品牌图标，名称回退逻辑保持现状。
- 上下文按钮位于组合条右侧，使用左分割线和现有 `CircularProgress`。
- 上下文数据不可用时不渲染上下文按钮，模型按钮自动占满组合条。
- 两个按钮保持独立焦点、可访问名称和点击行为。

### 定位按钮

定位按钮使用清晰的列表定位图标，并提供 `taskDetail.userInputIndex` 下的可访问文案。

- 点击后打开对话定位底部抽屉。
- 可用定位条目少于等于一条且非加载状态时，按钮不渲染。
- 加载状态继续使用现有 Spinner 和接口状态。

### 更多按钮

更多按钮使用三点图标并提供“更多任务工具”的可访问名称。

- 点击后打开任务工具底部抽屉。
- 技能、文件和预览始终按现有 `taskInteractive` 条件禁用。
- 发布入口继续按 `canPublishWebsite` 条件渲染，并按 `canInput` 条件禁用。

## 对话定位底部抽屉

`TaskUserInputIndex` 新增移动端按钮变体，同时复用现有数据加载、合并、跳转和高亮逻辑。

底部抽屉行为：

- 从屏幕底部滑入，背景显示遮罩。
- 高度最大为视口的 70%，列表区域内部滚动。
- 顶部展示标题和简短说明。
- 保留“加载更多”、定位中 Spinner、条目省略和错误提示。
- 点击条目后执行现有 `handleJump`。
- 跳转成功后关闭抽屉，目标消息保持现有高亮动画。
- 点击遮罩、下滑、关闭按钮或 Escape 键均可关闭。

手机端不渲染常驻圆点栏和 280px hover 面板。桌面端继续使用现有圆点栏、hover 展开面板和定位逻辑。

## 更多任务工具底部抽屉

任务详情页新增受控 Drawer，内容使用两列网格：

- 技能：打开技能更新对话框。
- 文件：切换文件侧边面板。
- 预览：打开预览对话框。
- 发布：打开发布确认对话框，仅在 `canPublishWebsite` 为真时渲染。

每个工具按钮包含图标、标题和当前状态提示，最小高度为 64px。点击有效工具后先关闭 Drawer，再调用现有处理函数，避免两个遮罩层同时显示。

文件和预览按钮继续显示现有计数。当前面板或对话框已打开时，按钮使用现有选中态颜色。

## 桌面端设计

768px 及以上保持现有结构：

- 模型、上下文和工具按钮位于同一行
- 技能、终端、文件、预览和发布保持直接入口
- 操作按钮保持 28px 紧凑高度
- `TaskUserInputIndex` 保持右侧圆点栏和 hover 展开面板
- 所有文案、状态、键盘焦点和事件处理保持现状

## 组件边界

### `task-detail.tsx`

- 负责手机端紧凑页头和更多任务工具 Drawer。
- 根据 `isMobile` 选择定位组件的手机或桌面呈现位置。
- 保持模型、上下文、面板和发布状态为唯一数据源。

### `task-user-input-index.tsx`

- 继续负责定位数据、加载状态、当前条目、跳转和高亮。
- 新增明确的手机按钮变体。
- 抽取并复用条目列表内容，避免桌面面板与手机 Drawer 产生两套数据逻辑。

不新增全局状态，不改变 API，不改变虚拟消息列表接口。

## 可访问性

- 模型、上下文、定位和更多入口具有独立可访问名称。
- 手机端常驻按钮触控尺寸至少为 44px。
- Drawer 包含可访问标题和说明。
- Drawer 打开后焦点进入面板，关闭后回到触发按钮。
- 工具按钮禁用态使用原业务条件并暴露给辅助技术。
- Escape 键和 Drawer 标准关闭手势可以关闭面板。

## 边界与错误状态

- 320px 下模型名称受控省略，其余入口保持完整。
- 当前模型缺少详情时显示现有名称回退，不渲染错误品牌图标。
- 上下文不可用时模型按钮填满组合条。
- 定位索引接口失败时继续显示现有 toast，抽屉可正常关闭。
- 历史消息尚未加载时继续按现有分页逻辑加载并定位。
- 发布权限缺失时更多 Drawer 自动使用其余三个工具填充网格。
- 横竖屏切换时通过 `isMobile` 重新选择呈现方式，只保留一个定位组件实例。

## 测试设计

### 自动测试

1. 更新手机页头结构测试，验证单行布局、模型品牌图标、组合式上下文、定位和更多按钮。
2. 验证手机端定位和更多按钮具有 44px 触控尺寸与可访问名称。
3. 验证更多 Drawer 包含技能、文件、预览和条件发布入口。
4. 验证工具点击先关闭 Drawer，再调用现有处理函数。
5. 新增定位组件响应式测试，验证手机 Drawer 和桌面圆点栏使用同一条目列表与跳转逻辑。
6. 验证手机模式不渲染绝对定位圆点栏。
7. 运行相关 Node.js 测试、frontend ESLint、TypeScript 和 online build。

### 人工验收

使用 online 预览验证 320px、375px、390px、430px 和 1280px：

- 短模型名与长模型名
- 模型图标存在和回退
- 上下文存在和暂不可用
- 定位列表为空、一条、多条和分页加载
- 定位跳转、高亮和自动关闭
- 更多工具的默认、禁用、选中和计数状态
- 发布入口显示和隐藏
- Drawer 遮罩、下滑、关闭按钮和 Escape 关闭
- 中文和英文界面

验收结果应满足：

- 手机页头保持单行且无控件碰撞
- 消息内容无定位栏遮挡
- 页面无横向滚动
- 所有常驻按钮和 Drawer 操作可准确触控
- 模型图标、字体族、字号、字重和行高正确
- 桌面端页头与定位器保持原行为

## 范围边界

本次只调整 Web 任务详情页手机工具栏、手机任务工具 Drawer 和对话定位器的响应式呈现。消息数据流、虚拟列表、定位 API、模型切换、上下文操作、文件与预览面板、发布流程以及 React Native 页面保持原实现。
