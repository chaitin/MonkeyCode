## 终章(2026-08-18 用户终案:工作台升级为主界面)

- 行政 = 行右键 改名(行内输入)/归档/删除(ListRow 全套复用),
  **项目全套**(2026-08-18 报障「项目的 archive 没有了」后按旧侧栏对表
  补齐:组头右键 在此新建/归档项目、组头拖拽排序、项目内已归档任务小节、
  底部已归档项目小节;根因教训:分组必须吃全量含归档,先滤再分组则
  小节恒空;同日二次报障「本地的 sidebar 完全不对」——图标/名称/快捷加
  三连,遂**逐项对表**旧组头:Folder/FolderOpen 随开合、裸项目名(工作台
  消歧特例撤销,全路径进组头 title)、waiting 黄徽标、hover「+」快捷新建
  常驻占位、右键菜单回 newTaskIn 键且传 g.key、拖拽热区挂 li + 落点线
  绝对定位(旧注释里的两条教训),并撤任务列「运行中」置顶区——行留组内,
  等待感 = 组头徽标 + 行尾状态点;装载卡的运行中置顶保留,快挑场景仍值),
  会话归档小节(mc.archivedOpen),待办组(TodoSection 原件迁入,
  mc.collapsedGroups 哨兵键不变;onOpenCloud 契约升级带 id → 装载入格);

  mc.lastSession 播种首叶;

### 单格融合(2026-08-18 用户:「只有一个任务时,任务 header 融入 app header、
边距不要,会好看么?」——试了,好看,定案)

- 依据:卡片语汇(圆角/边/画布衬)是"多格并存"的信号;独格时它是冗余
  家具,融合后即经典单文档形态(标题在顶栏,内容满幅)。
- 形态:total===1 且非放大态 → 格细头不渲染,**状态点+标题上浮进视图头**
  (标题即撑开段,拖拽区),右端跟簇 文件/向右拆/向下拆/更换(**放大与
  关闭不上浮**——独格两者无义,关闭本就置灰);画布衬/底/圆角归零,格
  本身改承 rounded-tl-box(内容块内嵌 L 形拐角的语言保持连续)。
- 内嵌新建盖着独格时标题簇让位回空段(与卡片态藏细头同构)。
- **放大态不融合**:那是多格的临时独占,回程钮在细头上,融合会把回程
  吞掉;卡片+焦点环的样子也正好在提示"这是临时态"。
- slotHead(槽位显示体)从 renderPane 抽出共用;拆/关跨过 1 格阈值时
  卡片↔融合互切,SplitView.test 有专测钉住(细头钮消失/上浮、p-3 与
  卡边归零、拆分后回卡片)。

## 背景

用户在大屏显示器上同时驱动多个本地 Agent 任务时,只能靠侧栏逐个切换:
后台任务的等待审批/提问要经角落 toast 或侧栏 attention 才知道,处理必须
切走当前会话。希望增加一个"分屏"入口,可选 1 / 2 / 4 个任务同屏展示、
同时交互——审批、答复、追问都不用切屏。

## 可行性结论(已核实)

**壳侧零改动。** 多会话同时在线本来就是壳的既有能力:

- 每会话独立事件通道 `frames:{sid}` / `conn-status:{sid}`,独立 journal,
  帧批量缓冲按会话隔离(`session.rs` 的 `opened` 是 per-session 标志);
- `session_close` 只把**该会话**的 `opened` 置 false,互不牵连
  (session.rs:1013);
- `useSessionFeed` 是按实例注册监听、按实例 open/close 的
  (ui-next/src/features/chat/useSessionFeed.ts),多实例天然并存。

唯一硬约束:**同一会话禁止同时出现在两个格子**——`session_close` 无引用
计数,先卸载的实例会把另一个实例的实时流掐断。槽位赋值单点判重即可。
模式切换(单会话视图 ↔ 分屏含同一会话)是安全的:React 先跑旧树 cleanup
(close)再挂新树 effect(open),次序天然正确。

  拆成那个形状时存在,而那是他的显式构造。演进留档:2×2 直线切分数学上
  只有三条可动线,预设四格(先竖切)的贯通竖线仍是"拖它 = 两列同变",
  用户想要别的形状就自己拆(比如先横切:单格 → 向下拆 → 两格各向右拆)。
- 每格是**全交互**的会话视图:composer、审批卡、提问卡、任务面板齐备
  ——"同时执行"的价值就在于不切屏处理等待项,只读监控墙不满足需求。
- 空格子有明确的任务装载入口(选已有会话 / 新建任务)。
- 焦点模型:同一时刻恰有一个焦点格,审批快捷键只作用于焦点格。
- 本地任务与对话(kind=chat)会话都可入格;空闲会话也可入格
  (分屏既是监控台也是工作台)。

## 非目标

- 云端任务入格(CloudTaskView 与会话视图同构,留作 v2 扩展)。
- 多 OS 窗口方案(App 级单例——意图消费/横幅/toast/窗口标题——都按单窗口
  架构;且用户要的是窗口内的"tab")。
- 格内独立侧栏;装载卡过滤框留观察再议(侧栏搜索曾被定案撤下,不预建)。
  (曾列非目标后被用户需求推翻的:全窗沉浸、任意形状布局——树模型已覆盖。)
- 格内提问大纲(贴边点列在窄格里挤占行宽,隐藏)。文件抽屉曾同列
  非目标,2026-08-16 用户报障「看文件的功能咋没了」后回归:细头
  「会话文件」开全局 FilesDrawer,一次一格。

### 命名与入口:主区视图动作;**全窗沉浸**

  丢的两样:屏外等待的持久信号、满格时的装载动线):左缘 w-side 列,
  顶部计数行常显 N 项目·N 任务,运行/等待仅 >0 追加彩色(2026-08-18

  换位 SWAP_MIME 并存);已入格行照列(行尾小网格标记,点击定位)——
  装载卡则判重排除。视图头 ⟨☰⟩ 一键收起回全沉浸,开合态记忆
  (mc.workbenchListHidden,语义取反使缺省=展开)。任务列在场时空格
  是轻提示卡(列表不重复两份),收起时回落完整装载卡。

  ——分屏格里可能是早已删掉的会话,拿它当开机首屏没有意义)。

- **布局树模型**(tree.ts):叶 = 槽位(0..5,上限 6),内部节点 = 一次
  切分(dir + ratio)。拆分 = 叶变切分(新格取最小空槽号、原格在前);
  关闭 = 兄弟上位(tmux 收格),槽位内容一并清档(关格是显式动作,
  不同于换模板的"藏而不清");换位 = 两叶槽号互换(内容跟格走)。
  模板(1/2横/2纵/4)= 四棵预设树,套形状不套比例;模板钮按下态按
  sameShape(比例被拖过仍算同档)。「放大」= 临时独占渲染单格,树不变。
- 槽位模型:定长 6 的 `(sid | null)[]`;树上不在场的槽位留档,换回带它
  的模板即恢复。
- 焦点格:点击格内任意处取得焦点,`ring-primary`(内圈)标识;
  装载/更换会话后焦点格 composer 自动聚焦(对齐 select() 的既有行为)。
- 屏外任务路由:格内可见会话的 D3 角落 toast **抑制**(通知口径从
  「非当前会话」扩为「不在任何可见格」);屏外会话的等待/终态 toast
  照发,**点击不再切回普通视图,而是装载进叶序第一个空格(无空格则
  焦点格)**——人留在作战室里处理新到的等待项。装载即 dismissSession
  (视为已读)。删除会话时对应槽自动空槽。

### 交互走查(主路径)

1. 点 rail 底部「工作台」钮 → 全窗接管:左格 = 当前会话(带焦点环),右格 = 装载卡;
2. 装载卡点某任务 → 该格挂载会话、取得焦点、composer 聚焦;
3. 左格弹审批 → 其细头状态点转 warning 脉动;点左格任意处夺焦 →
   Enter 允许(快捷键只作用于焦点格);
4. 要并行第三个任务 → 任一格细头「向右/向下拆分」长出新格(或视图头

5. 屏外任务弹 toast「等你确认」→ 点击 → 装进叶序第一个空格(无空格则
   焦点格),沉浸不被打断;装载卡判重排除已入格,禁重复约束由装载
   单点守住;
6. 布局不顺手 → **按住格头标题拖到另一格**交换位置(落点虚环高亮);
7. 某格点 ⛶ 放大 → 临时独占,再点原位返回;点 ✕ 关闭格子 → 兄弟上位,
   会话本身照常后台运行;
8. 视图头 ✕ 退出 → 回普通三列视图;树与槽位已持久化,下次点开原样恢复。

### 降噪(2026-08-18 用户报障「现在很乱」后的定案)

乱的根源不是布局而是**重复的家具**:单会话视图只出现一份的周边控件在
四格里每格复制一份(错误横幅 ×4、composer 控制行 7 控件 ×4、细头六连钮
×4 ≈ 60 个常驻非内容控件)。原则:**焦点格享受全套,非焦点格只留
身份 + 状态 + 内容**。四招:

- 连接/错误横幅(§3 内嵌条)在 pane 形态默认收成角落警示小图标
  (全文恒在 title/aria,点开展开原横幅、再点收回);
- **composer 焦点收敛**:仅焦点格挂完整输入卡 + 控制行 + 任务面板,
  非焦点格一条单行轻输入条,点击夺焦展开(草稿在 stash 按会话留档,
  收起不丢);
- 细头六连钮 hover 显隐(invisible→visible 常驻占位不挤布局,§6.2
  铁律;更换态/独占态强制可见——开着的开关不能藏);
- 细头铺 base-200 淡底,格读作一张卡(边界不再只靠 1px 线)。

## 技术设计

### 改动面(全部在 ui-next)

1. **ChatView pane 变体**(`variant?: "full" | "pane"`,默认 full 不回归):
   - pane:隐藏 52px 大头(细头由 SplitView 经 props 注入动作)、
     OutlineNav、FilesDrawer 入口;
   - 列宽换 `.chat-measure-pane`:`max-width: min(64rem, 100% - 2rem)`
     ——**去掉 48rem 地板**。地板是给全宽主区设计的,四分格宽约
     ~790px(1080p)时 768px 地板必然横向溢出。新类与 `.chat-measure`
     相邻定义(app.css 头注要求的"只动一行"约束对两条列各自成立);
   - **审批快捷键门控**:`useApprovalHotkeys` 加 `enabled` 参
     (仅焦点格 true)。现状是 window 级 keydown 按实例注册,四格同挂时
     一次 Enter 会把**所有**格子的待审批一起应答——这是 v1 必修项,
     不是优化。
2. **features/split/ 模块**:`tree.ts` 布局树纯逻辑(校验/叶序/拆分/
   收格/换叶/按路径改比例/形状等价,单测钉死)、`slots.ts` 槽位纯逻辑、
   `useSplitState` 状态机(App 持有)、`SplitView` 递归渲染 + 细头动作 +
   装载卡 + 焦点管理、epoch 透传(引擎自愈整格重建,与主区同款)。
3. **App 接线**:rail 钮、渲染分支插位(分屏在场时 **rail 与 Sidebar 都
   不渲染**)、toast 点击路由(splitOpen 时装格不切视图)、通知抑制口径、
   windowContextLabel 加分屏态、focusRequest 路由到焦点格。
4. **持久化**(prefs.ts):`mc.splitTree`(布局树 JSON,校验权威在
   tree.ts,坏档整树回缺省)、`mc.splitSlots`(JSON,长度 6)。槽位自愈
   只在 sessionsList **成功**返回后按全表剪枝(失败保留——与「失败不能
   用空结果覆盖列表」同一铁律)。分隔线拖拽走 FilesDrawer::trackPointer
   同款收尾纪律(mouseup 与卸载兜底双路收回 body 的全局 cursor/
   user-select)。
5. **LAYOUT.md 修订**:§1 登记分屏全窗例外(rail/侧栏都让位、mac 窗控
   移居)、§4 视图形态新增分屏 + 渲染优先级、rail 结构
   (标记 → 导航 → 分屏 → 设置)。
6. i18n 全量补 key;颜色一律主题 token(CI check_theme_tokens.py 拦截)。

### 性能预算与升级路径

- 进入分屏 = 最多 4 个尾部回放窗口(各 ≤3000 帧)并发落地,均已走

## 边界与故障

- **格区宽度总闸**(2026-08-18 溢出事故):嵌套 flex 的内在宽度上传只要
  有一环缺 min-w-0,整棵格区就跟着最宽内容走(Chrome 实测:一段长代码把
  格撑到 8054px、文档 9857px,右格整个被推出屏外)。总闸两处 =
  data-split-grid 与其父行容器,类名机检钉在 SplitView.test;真实布局
  回归用 playwright-core + 系统 Chrome 的临时探针手跑(素材:长代码/
  长词/宽表格/行内长码)。

- 格内会话被删:App 删除链路成功后 refresh,SplitView 据全表剪枝该槽。
- 引擎崩溃/重启:epoch 自增,四格与单会话视图同一套幂等重开。
- 会话打开失败:openError 在格内原位外显(useSessionFeed 已带该通道)。
- 小窗口进 4 格:列宽无地板后不溢出,只是挤;不做最小窗口强制。
