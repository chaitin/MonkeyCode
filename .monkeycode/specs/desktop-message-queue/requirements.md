# Requirements Document

## Introduction

桌面端消息队列允许用户在当前任务执行期间连续提交多条后续消息。系统按队列顺序逐条发送消息，并在输入区上方提供可折叠的队列管理面板。

## Glossary

- **消息队列**：当前会话中尚未发送给 Agent 的有序消息集合。
- **队列项**：一条待发送消息及消息关联的附件。
- **当前轮次**：Agent 正在处理或前端正在提交的消息轮次。
- **待执行项**：消息队列中尚未开始发送的队列项。
- **队列面板**：输入框上方用于展示和管理待执行项的可折叠区域。

## Requirements

### Requirement 1：连续入队

**User Story:** AS 桌面端用户, I want 在 Agent 工作时连续发送后续消息, so that 我可以一次安排一批独立问题。

#### Acceptance Criteria

1. WHEN 用户在当前轮次执行期间发送有效消息, 桌面端 SHALL 将消息追加到当前会话的消息队列末尾。
2. WHEN 用户在消息提交尚未由会话帧确认期间再次发送有效消息, 桌面端 SHALL 将消息追加到当前会话的消息队列末尾。
3. WHEN 用户提交消息成功进入消息队列, 桌面端 SHALL 清空输入框中的正文和附件。
4. WHILE 当前会话存在待执行项, 桌面端 SHALL 保留每个待执行项的正文和附件关联。

### Requirement 2：顺序执行

**User Story:** AS 桌面端用户, I want 队列消息按照可见顺序依次执行, so that 多个问题的处理次序符合我的安排。

#### Acceptance Criteria

1. WHEN 当前轮次结束且消息队列非空, 桌面端 SHALL 发送消息队列首项。
2. WHILE 一个队列项正在提交或执行, 桌面端 SHALL 保持其余队列项处于待执行状态。
3. WHEN 队列首项被会话帧确认接收, 桌面端 SHALL 从待执行项中移除该队列项。
4. IF 队列首项提交失败, 桌面端 SHALL 将该队列项保留在队首并显示发送失败信息。
5. WHEN 当前轮次被用户停止, 桌面端 SHALL 保留全部待执行项，并在会话重新进入可发送状态后继续发送队首项。

### Requirement 3：队列可见性

**User Story:** AS 桌面端用户, I want 在聊天输入区附近查看队列, so that 我可以确认后续任务数量和执行顺序。

#### Acceptance Criteria

1. WHILE 消息队列非空, 桌面端 SHALL 在输入框上方显示队列面板。
2. WHILE 队列面板处于折叠状态, 桌面端 SHALL 显示待执行项数量和队首消息摘要。
3. WHEN 用户展开队列面板, 桌面端 SHALL 按执行顺序显示全部待执行项。
4. WHEN 消息队列变为空, 桌面端 SHALL 隐藏队列面板。
5. WHILE 队列面板展开且内容超过面板最大高度, 桌面端 SHALL 在面板内部提供垂直滚动。

### Requirement 4：队列管理

**User Story:** AS 桌面端用户, I want 调整、编辑和删除待执行消息, so that 我可以在消息开始处理前修正安排。

#### Acceptance Criteria

1. WHEN 用户对待执行项执行排序操作, 桌面端 SHALL 按调整后的顺序更新消息队列。
2. WHEN 用户编辑待执行项并确认, 桌面端 SHALL 使用更新后的正文和附件替换原队列项。
3. WHEN 用户删除待执行项, 桌面端 SHALL 从消息队列移除该队列项。
4. WHILE 队列首项正在提交, 桌面端 SHALL 禁用该队列项的排序、编辑和删除操作。
5. IF 编辑结果不包含正文和附件, 桌面端 SHALL 保持原队列项并提示消息内容不能为空。
6. WHEN 用户使用键盘操作排序控件, 桌面端 SHALL 支持将待执行项向前或向后移动一个位置。

### Requirement 5：会话隔离与生命周期

**User Story:** AS 同时使用多个本地会话的用户, I want 每个会话维护独立队列, so that 后续消息不会发送到错误会话。

#### Acceptance Criteria

1. WHEN 用户切换会话, 桌面端 SHALL 保存离开会话的消息队列并恢复进入会话的消息队列。
2. WHEN 后台会话完成当前轮次, 桌面端 SHALL 从对应会话的消息队列发送队首项。
3. WHEN 用户删除会话, 桌面端 SHALL 删除对应会话的消息队列。
4. WHILE 应用进程保持运行, 桌面端 SHALL 在会话视图卸载后保留对应消息队列。
5. WHEN 桌面应用重新启动, 桌面端 SHALL 以空消息队列初始化会话。
