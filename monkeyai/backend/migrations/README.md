# 数据库迁移

版本 `60` 为模型网络黑名单开放独立的 `model_network` 设置键，不创建默认配置，不修改 MCP 黑名单。已有模型网络配置时回退会拒绝执行，避免静默丢失规则。

本次按重新部署要求，将原 `000001` 至 `000013` 的最终结构收敛到一版初始化迁移：

- `000001_initial_create_schema.up.sql`：完整创建身份与邮箱认证、OAuth、调用密钥、分组、设置、模型、资源、连接与多凭证、专家、计费、统计索引及审计结构。
- `000001_initial_create_schema.down.sql`：按依赖逆序删除本版本的表、序列和计费流水保护函数，仅用于可丢弃测试数据库。

首次部署必须使用全新的 PostgreSQL 数据库或数据目录。重建容器但复用旧数据目录不构成全新初始化。收敛前的旧迁移历史不支持直接升级到当前迁移历史，也不能通过 `force 1` 代替数据迁移；需保留这类旧数据时应另行制定迁移方案。使用收敛后迁移历史的现有数据库正常追加迁移，版本 `14` 的升级步骤见下文。

从 `backend` 目录执行：

```sh
migrate -path migrations -database "$MONKEYAI_DATABASE_URL" up
migrate -path migrations -database "$MONKEYAI_DATABASE_URL" version
```

成功后 `schema_migrations` 应为 `version=59, dirty=false`，再次 `up` 返回 `no change`。可丢弃测试库执行 `down -all` 后再 `up`，应能完整重建。

初始化不预置用户、分组或业务设置。首次管理员由后端按部署环境变量创建，RustFS Bucket 由后端启动流程检查并按需创建。团队根节点仅用于界面展示，名称读取 `settings.branding.workspace_name`；顶层分组使用 `parent_id IS NULL`，成员关系通过 `group_users` 显式维护。

连接直接保存配置，专家直接关联连接；同一用户可以为同一连接创建多份凭证，每个连接最多保留一份未撤销的集中凭证。工具的组合外键防止跨连接引用凭证。计费账户校验冻结金额非负，允许调用结算后余额为负，流水触发器禁止修改和删除。

`migrations` 仍是结构定义的唯一来源。修改后在 `backend` 运行 `make generate` 更新 sqlc schema 与生成文件，再运行 `make check`；数据库集成测试验证有业务数据时的 `down → up`。迁移文件名和 up/down 配对由 `go test ./migrations` 检查。

新增迁移 `000003_group_quota_inheritance` 移除 `users.billing_group_id`，额度直接使用 `group_users`：个人自定义优先，多组取最高有效额度，无组继承团队。已有成员无需手工对齐；现有账户、余额与历史分组快照不修改。升级前备份，前后端需同步发布；down 仅恢复旧字段结构，不能恢复已移除的独立归属数据。

新增迁移 `000004_credit_account_overdraft` 允许余额为负及冻结额超过余额，仅保留冻结额非负约束。付费调用在可用积分（余额减冻结额）大于零时获准执行，完整预留费用，按实际用量结算；零或负可用积分不再接收新的付费调用，免费调用不受影响。百智云钱包自身的预扣限制不变。回滚前需结清负余额并释放超额冻结，否则回滚会失败，不会截断余额或改写历史流水。

本次单版重置是重新部署的特定安排。后续正式发布后的 schema 变更正常追加六位递增迁移版本，已发布迁移不再改写。字符串统一使用 `text`，候选值使用 `CHECK`。

## 模型统计的员工维度（版本 59）

先停后端及分区维护进程，备份并预留回填和重建唯一索引的时间、空间；执行 58、59 后启动配套后端。59 在同一事务内锁住事实表写入与两张汇总表，把北京时间今天及之前 89 天的小时汇总替换为现存调用、积分流水按员工重算的结果。缺失的明细不估算、不分摊，不改账本。更早的汇总保留为无员工归属，超管仍可统计；记录固定回填起点是为了使迟到的修正或删除能扣回正确的历史桶，不是按请求时间滑动截断。

父表和按月分区不变。主管只看请求时管辖的员工，不能从接口指定员工范围。回退前停后端；down 将各员工及无归属桶合并回 58 的原有粒度，保留回退时的合计，不恢复回填时因明细缺失产生的历史差异。

## 模型小时统计月分区（版本 58）

两张模型小时汇总表按 `hour_start` 的北京时间自然月分区，仍以原表名读写。升级直接搬迁已有汇总，不扫描调用／账本明细，不增加员工维度。两张表的主键、统计口径及触发器不变，不自动删除历史分区。

升级前备份并暂停业务读写，预留复制两张汇总表及其索引的空间；升级和降级均在单个事务中持有两张表的排他锁。升级为已有数据涉及的月份建分区，并预建本月和后两个月。新版后端的交易／调用分区维护任务启动后每日预建，失败后一分钟重试；未预建月份的迟到或超前写入先落默认分区，下次维护会原子搬入对应月份。自动维护合计最多搬迁 10,000 行；超过上限时业务仍可读写默认分区，后台告警并改为次日复查。维护窗口可用 `SELECT stats_model_create_month(月内时间);` 逐月手动搬迁，再执行 `SELECT stats_model_ensure_months(now());`。首次迁移不受自动搬迁上限影响。降级前停止新版后端；down 将所有月份及默认分区的数据原样复制回普通表。

## 可选宿主机名称

版本 `54` 放宽 `hosts.name` 约束以允许空名称，保留 128 字节上限。

## 分组主管名单

版本 `53` 在 `group_users` 增加 `is_supervisor`，原有成员默认不是主管。升级后部署新版后端和管理端；回滚此迁移会丢失主管配置，不改变分组成员关系或用户角色。

## 取消宿主云电脑数量限制

版本 `52` 新增环境归档时间，用于从默认列表移除离线宿主上已请求删除的环境；不会代替宿主的清理确认。

版本 `51` 删除 `hosts.max_environments`，同步移除管理端输入／详情展示及接口字段。自动调度在满足授权、调度开关、在线、协议、镜像及计费准入的宿主中，优先选择现有环境数最少者，不按环境数量或物理 CPU／内存总量拒绝新建。

部署前备份、停止旧后端，执行迁移后同步部署新版后端和管理端。本次不执行实际迁移，也不修改客户端应用。已有云电脑、授权及账务不改写；down 仅恢复默认0的旧字段，不能恢复历史上限，回退旧服务前须重新配置。

## 取消每用户云电脑数量限制

版本 `50` 删除 `host_environment_configs.user_max_environments` 列和 `environment_quotas` 表，同时移除个人配额管理接口与宿主目录 quota 字段。迁移51继续取消宿主总数量上限；授权、积分准入和已有云电脑不受影响。

部署前备份并停止旧后端，执行迁移后同步部署新版后端和管理端；客户端需停止依赖 quota 字段，本次不修改客户端应用代码。旧个人配额值会被删除，down 仅恢复默认每用户上限3和空配额表，不能还原历史配置。禁止旧服务连接已升级结构。

## 云电脑全局规格升级

版本 `49` 新增 `environment_specifications` 和 `environment_specification_catalog`，将可选 CPU／内存规格从宿主配置中独立出来。初始目录包含 1 核 2 GB 规格，不自动发布历史宿主的资源组合。管理员可以修改或删除默认规格，清空后不会自动补回。

先应用迁移，再同步部署后端与管理端。客户端需通过 `GET /api/v1/environment-specifications` 获取目录，新建提交 `specification_id` 与 `specification_version`；不携带规格的新请求将被拒绝。此变更不修改客户端应用工程，需由客户端工程按接口文档接入。

历史宿主 resource 数据保留，但不再参与宿主目录、配置写入或新建调度。授权仍按宿主维护，数量限制在迁移50／51取消；计费仍使用全局单价及实例实际资源快照。已有环境数据、账务与幂等记录不改写，规格修改／删除不阻止旧实例按原快照重启。

回滚前必须停止新版服务并备份规格目录；down 会删除这两张规格表，不删除已有环境或账务，但不会将全局规格转换回宿主预设。旧版新建逻辑依赖旧预设，新版创建的宿主配置可能没有该值，因此回退后须单独检查宿主配置。

## 云环境整小时预付升级

云电脑计价统一保存在 `settings.billing.environment`，由费用设置中的「云电脑扣费规则」配置。旧宿主单价不再读取或覆盖全局配置；云电脑始终按全局单价计费，不受系统计费开关控制，零单价不扣积分；未配置时 CPU 默认每核每小时100积分，内存默认每GB每小时50积分（GB=1024³字节）。旧配置中的独立 enabled 不再生效，已有自定义单价保持不变。宿主配置接口不再接受计费修改，历史账单及已购买小时保持原价。

版本 `47` 为计费区间增加 `prepaid_until`。启动前在同一事务中扣除一小时费用并保存有效期；到期续扣，余额不足则停止，不允许新增预付产生透支。提前停止不退款，同一环境在已购买小时内重启不重复扣费；启动准备时间包含在购买的一小时内。调价从下一次续费生效，已付费小时不会因余额变化失效。

必须停止旧后端、执行迁移，再启动新后端，禁止旧计量进程与新版本并行。旧按秒记录只结清已确认未结算部分，历史价格及断线空档不重算；新购买小时不会按秒重复结算。暂停期间不续费，恢复后先购买当前小时，不追扣暂停空档。扣费周期归属于购买时的账户，不拆分跨账户周期的一小时。

分钟级后台检查用于恢复和停机检查，不代表每分钟扣款；已知到期时间会提前安排唤醒。存在任何预付账务记录时，`down` 拒绝删除字段，避免丢失已购买时长；先备份并归档账务后才能回退。

## 实时工具目录升级

版本 `42` 移除工具调用原始表到 `mcp_tools` 的工具外键，稳定工具 ID 和调用名称快照仍保留在调用／计费记录中。迁移通过分区状态中的原始表 OID 定位，兼容尚未切换与已切换的调用周分区。不清理历史工具目录，不改写历史调用；新后端只持久化无认证／集中认证的显式开关和单价，不保存独立认证工具或远端描述／Schema。必须先执行迁移再启动配套后端，前端需同步发布以在首次保存配置时提交工具名。

`down` 以 `NOT VALID` 恢复原始表外键，不伪造工具目录记录，也不删除已存在的实时工具调用历史。回滚前停止新后端，恢复后的约束仅校验后续写入。

## MCP 网络访问黑名单升级

版本 `43` 允许在 `settings` 中保存 `mcp` 网络访问设置，不预置业务配置；未配置时黑名单为空。须先迁移，再通过管理端保存 IPv4/IPv6 CIDR 黑名单。

`down` 在已有 `mcp` 设置时拒绝回滚，避免丢失已配置的网络限制；应用回退可以保留该设置。需回退数据库时，应先备份并按部署方案处理该设置，不能只清空黑名单列表后直接执行 `down`。

版本 `28` 首次升级会锁定调用、计费交易和账本写入，并在结构变更锁持有期间阻塞调用表读取；同时扫描历史数据完成回填，请停止旧后端并安排迁移窗口；升级后每次调用完成、状态/用量修正、退款均在原事务内增量维护。版本 `28` 回滚只删除统计投影与新增标记，保留原始调用和账本，再次升级可完整重建。

版本 `29` 的结构准备仍需维护窗口；启动新后端后，账本 worker 在后台按固定水位分批搬迁，数据库迁移版本为 29 不代表账本已经切换。通过 `billing_ledger_partition_state` 查看进度。启动及每 24 小时预建当前与未来 8 周，默认分区接受意外时间。观察期保留旧表事务内镜像，可用 `billing_finish_ledger_observation()` 显式结束，历史数据不自动删除。回滚前停止后端及业务读写；down 始终从权威分区表补齐旧副本缺失记录，不能只信任观察期标志，需预留维护时间与空间。默认分区总积压超过 10000 条时暂停自动 DDL 并告警，避免 ATTACH 扫描巨大默认分区。详见 [账本周分区运行方案](../../design/billing-weekly-partitions.md)。

版本 `34` 保持 `sessions` 普通表，将轮次按上海自然月分区。结构准备后由独立会话 worker 分批校准 `turn_count` 和回填事实，状态见 `session_turns_partition_state`；迁移版本为 34 不表示数据已全部切换。两个历史列表改用 `has_next`，前后端需配套发布，未校准的对话数暂为 `null`。回滚始终恢复权威数据的新增、修改和删除。发布窗口、默认分区搬迁、结束观察和回滚操作见 [轮次月分区运行方案](../../design/session-turn-monthly-partitions.md)。

版本 `35` 将交易／调用周分区预建中的 `55P03` 锁竞争转为返回 `false`，本次尝试整体回滚，由新后端按表一分钟后重试；成功后仍间隔 24 小时检查。默认分区积压超限、分区名称冲突等错误继续告警。只更新维护函数，不修改业务数据；down 恢复原错误行为。

版本 `36` 为 `users` 增加可空的 `custom_avatar_url`，不回填或修改已有 `avatar_url`；后者继续由 OAuth 同步。身份认证、成员、授权选择器、审计、账单、反馈、客户端和历史统计统一优先显示非空的自定义头像。本人头像上传/清除和密码修改不涉及成员创建与席位写入。须先执行迁移再启动新后端；新头像保存在现有对象存储。改密会同时取消已批准但未兑换的设备申请，新增部分索引按用户查找这类申请。宿主 OAuth 写入应继续仅更新同步字段，不应写入 `custom_avatar_url`。down 会删除自定义头像覆盖信息、密码尝试记录和设备批准索引，不删除同步头像或密码，也不会遍历清理对象存储。

版本 `37` 创建 `oauth_pairing_requests` 和过期、创建者状态、设备码摘要索引；手机端只取得账号级登录态，不登记执行设备。新后端修改密码时依赖该表撤销未兑换配对，因此须先迁移再启动。down 会删除全部一次性配对记录，再 up 只恢复空表；已签发的 OAuth 授权与令牌不由此表管理。

版本 `23` 回滚会恢复视频供应商约束；版本 `24` 回滚会移除远程执行新增结构；版本 `26` 回滚会恢复设备平台枚举，需先处理旧枚举以外的平台记录，否则回滚失败，不会静默改写平台值。已有生产数据回滚前必须先备份并按部署方案确认，测试 down/up 只用于隔离数据库。

升级回归测试使用独立临时 schema，通过真实 `migrate` CLI 验证版本顺序、业务数据保留、冻结额清理、新增结构与重复执行，需要本地安装 `migrate`：

```sh
MONKEYAI_TEST_DATABASE_URL="postgres://..." go test ./migrations -v
```

`000024_remote_runtime` 的 up/down SQL 将当前工作树新增的远程执行结构作为一个版本执行，支持重复执行。重复升级保留已有授权族、刷新链、设备版本、会话摘要和密钥绑定；旧 token 只在尚未绑定授权族时回填。重复回滚会保留既有撤销时间和原因，重新升级不会恢复已撤销凭据。

`TestRuntimeMigrationsIdempotent` 使用真实 PostgreSQL 验证 `000024_remote_runtime` 重复执行、完整迁移组重跑及回滚后重新升级，并检查业务数据、约束和旧写入触发器。`migrate up` 的 `no change` 检查仍单独保留。

版本 `38` 为 `models` 增加embedding模型类型与配置；down恢复旧类型约束，需先处理embedding模型记录。版本 `39` 建立知识库、文档树、向量／全文分片及学习任务快照；down清理kb授权和标签并删除知识库数据，生产回退前必须备份。二者属于既有主线，云环境40不改写它们。

知识库文档树不使用数据库外键，父子关系在知识库锁内校验。向量模型通过不可变配置和模型ID标识：型号、地址、协议、供应商、类型及维度创建后不可修改；更换型号必须新建模型记录并切换知识库绑定。名称、密钥、代理及授权可更新。

### 000040_cloud_environments

云环境相关结构收敛为一个40版本。用户确认保留新主线38向量模型及39知识库，主线1～39不改；云环境不再占用38，不提供独立的计费和宿主授权迁移。40在同一事务中创建八表并扩展OAuth scope、宿主授权和环境账务类别；host授权约束保留主线kb类型，回退只清理host授权，知识库记录及权限不动。

| 表 | 职责 |
| --- | --- |
| `hosts` | 创建者user_id、宿主身份、激活／心跳、enabled及最大环境数，不保存接入／挑战状态或权重 |
| `host_environment_configs` | 每宿主规格、每用户默认数量和价格，无配置／价格revision |
| `host_upgrades` | engine升级任务历史及from_version，单宿主最多一个未完成任务 |
| `environments` | 环境目标／实际状态、精简执行配置、CPU／内存规格、监控及计费停机原因 |
| `environment_runtimes` | runtime实际版本及机器／公钥／实例／代次绑定 |
| `environment_operations` | 创建、生命周期和runtime更新的幂等请求及结果；创建键按用户唯一 |
| `environment_quotas` | (host_id,user_id)个人环境数量覆盖 |
| `environment_billing_periods` | 价格／规格快照下的区间、确认边界及持久结算进度，无价格revision |

不创建预设或控制锁表，不保留preset_id、旧全局配置、资源预留标记及停用的磁盘额度列。已有账户、交易和不可变流水继续复用，不增加钱包；存储暂不收费。

主线39正常up到40；从14升级仍依次执行15～40并保留主线业务数据。已经使用旧开发版38或此前拆分版本的数据库不能靠up、force或重放新版40修补结构；须使用原迁移包并单独制定保留数据的迁移方案，只有确认可丢弃的隔离测试库才能重建。本轮不自动清理或修改任何实际数据库。

新宿主enabled默认false、最大环境数默认0，管理员配置后才能分配；每用户默认环境数量为3，收费默认关闭、两项单价0，规格未配置。宿主和用户都按未确认删除的环境计数，停止仍占名额，确认删除才释放；降低上限不清理已有环境，重启不重复申请名额。允许分配规格总量超过物理CPU／内存，仅保留单环境运行限制和计费规格。授权复用resource_access_grants的host类型，新宿主由管理员保存范围，撤回仅限制新建／再次启动，不打断原运行与连接。

接入凭证由服务器级持久签名密钥签发，包含宿主ID、版本和有效期，不写宿主认证字段；签名文件位于MONKEYAI_RUNTIME_STATE_DIR下host-signing.key，权限0600，须随server状态保留。重发命令会撤销原待接入记录并创建新ID，不能在原安装过程中重发。首次注册绑定公钥并写activated_at，创建者来自管理员登录态。

心跳和环境交换使用v2签名，包含用途、服务端根地址、宿主ID、服务端/time返回的at和正文摘要。原子推进已接受业务报告时间，旧时间／重放拒绝，不能推进费用；不保存挑战或nonce。server、engine和installer需配套更新，保留宿主原私钥及配置。Server显式HTTP支持保留，第三方HTTPS校验不变。

up支持对本版最终结构重放，保留宿主配置、个人覆盖、受限或空授权、升级历史、环境／runtime身份及账务。控制路径先取按schema区分的PostgreSQL事务级advisory lock，再锁宿主、环境和账户，数量检查与创建同事务；不再有environment_defaults固定行。spec只保存执行配置，下发时从列组装ID／实例／代次／目标及CPU／内存，已有环境规格不跟随宿主配置变化。价格变化比较内容，只结束本宿主旧时段，余额耗尽不停止免费宿主环境。

账务类别同时扩展交易和账本的源表、周分区父表及已有分区，兼容回填及切换后的状态。收费需启用本地积分模式；服务端确认可用后按秒计量、每分钟结算，停止尾段及跨周期使用快照；失联未知时间不补扣，迁移不追溯收费或修改余额。

down在开放计费时段、已收费时段、交易／账本环境历史、待完成宿主升级／runtime更新或未确认删除环境存在时拒绝，整笔事务回滚，保留数据、权限和余额。允许回退时先撤销环境scope授权族和token、过期未完成申请及授权码，移除host授权，再按依赖删除八张表并恢复原账务类别约束。重复down不重复增加撤销版本，重新up不恢复已撤销凭据；回退不会操作宿主容器和持久目录，不能代替工作负载回收。

隔离PostgreSQL回归覆盖14→40、39→40、一次回退到39及down/up、最终schema、SQL重放保持受限授权／配置／快照、余额保留与财务历史保护，以及账本／交易周分区切换前后收费。schema/sqlc仅通过make generate生成。

版本 `41` 增加 `knowledge_base_documents.updated_by_user_id` 和 `knowledge_base_documents.content_updated_at`，全部可空；存量记录保持 null，不推断历史修改者或把学习更新时间当作内容修改时间。复用既有 `read_only/read_write`、知识库 revision 及 `schema_migrations`，不新增权限等级、独立授权版本或额外迁移记录表。迁移不更改已有授权、正文、分片或任务。须先迁移，再启动使用这些字段的新后端。

版本 `41` 的 down 删除文档的上述两个字段及知识库图标存储键字段，保留业务数据及既有权限。应用回退可保留新增字段；若执行 down，最后修改人和内容修改时间会丢失，再 up 只恢复空字段。历史 read_write 应在开放协作写入前核实授权意图，migration 不静默降级或升级授权。
