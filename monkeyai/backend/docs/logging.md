# 后端运行日志

后端以 JSON 输出安全的结构化运行日志。每个 HTTP 请求在完整路由入口生成本地 `request_id`，响应头为 `X-Request-ID`；客户端及上游同名头不能覆盖它。审计复用该 ID，模型的上游响应 ID 则写在 `response_id`，数据库中的原有对账 ID 语义不变。

普通请求完成记录为 DEBUG，健康检查成功不逐条记录。`http.request.completed` 表示 HTTP 处理结束；`model.call.completed` 表示上游或流式解析结束，两者可能发生在不同时间。HTTP 200、用量已知均不能单独证明模型调用成功。

## 配置

以下环境变量由创建根 logger 的独立入口读取；嵌入式 `server.Run` 使用调用方提供的最终 logger，不重新读取配置覆盖它。

| 环境变量 | 默认值 | 约束 |
| --- | --- | --- |
| `MONKEYAI_LOG_LEVEL` | `warn` | 启动参数 `--log-level` 优先 |

未设置环境变量和启动参数时，默认级别为 WARN；显式设置 `info` 或 `debug` 仍按指定级别生效。无效日志级别会使入口启动失败，不回显配置值。旧的 `MONKEYAI_LOG_DEDUP_*` 环境变量不再读取。

## 错误详情

所有达到当前日志级别的事件均即时逐条输出，不做去重、采样或定时汇总。根 logger 和派生 logger 使用同一输出链路，无后台日志调度器或关闭刷新要求。

`ErrorAttrs` 和 `Diagnostic` 保留完整的 `error_message`，同时输出 `error_code`、`error_type` 等分类字段。直接传入 `"error", err` 时，这些字段位于 `error` 对象内；传入错误字符串时保留该字符串。错误文本保留包装上下文、中文、多行及长消息，不截断。依赖检查错误保留依赖名和原始原因，HTTP 运行时错误与 panic 也记录原始文本。

普通属性仍过滤凭据、请求体、响应体和任意对象；错误文本本身按原文记录，可能包含错误来源携带的 URL、路径或其他信息。HTTP 错误响应仍使用原有通用文案，日志详情不会自动写入响应。

后台依赖检查每次失败都记录具体错误，实际检查恢复后输出一次恢复事件。请求 ID、源码位置、动态日志级别及审计关联继续保留。

错误处理遵循“向上返回或记录原始错误”的原则。异步任务、计费补偿、状态更新、事务回滚、流关闭、临时文件清理及响应写入均检查返回值；需要转换为客户端固定提示或继续降级处理时，先记录原始原因。事务已结束后的兜底回滚和已清理的临时文件按正常状态识别。日志输出自身失败时尝试写入 stderr，避免静默丢失输出故障。

## 部署

Compose 为各服务使用 `json-file` 轮转，默认每文件 20 MiB、保留 5 个文件，可通过 `MONKEYAI_LOG_MAX_SIZE`、`MONKEYAI_LOG_MAX_FILES` 调整。现有容器需要重建才能采用新的 Docker 日志驱动设置。重复故障会逐条写入容器日志，日志保留量由轮转配置控制。

Nginx 日志调整暂缓，沿用本次 PR 之前的 access/error 日志配置；本次后端日志改造不改变 Nginx 的输出格式、开关和日志诊断范围。
