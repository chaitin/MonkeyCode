# 镜像缓存治理

镜像缓存属于专用 containerd，目录固定为 `/var/lib/monkeyai-engine/containerd`。engine 不接受用户指定的缓存路径、任意 prune 参数或共享 containerd socket，也不删除项目、用户和 runtime 持久卷。

## 预算与准入

默认总占用预算 64 GiB，文件系统保留至少 8 GiB 和 100,000 个空闲 inode。可在 root 所有、0600 的普通文件 `/etc/monkeyai-engine/cache.json` 中调整：

```json
{
  "max_bytes": 68719476736,
  "min_free_bytes": 8589934592,
  "min_free_inodes": 100000
}
```

文件可省略；省略字段沿用默认值。总预算范围为 32 GiB～4 TiB，磁盘余量范围为 1 GiB～4 TiB，inode 余量范围为 10,000～10,000,000。未知字段、非对象、多对象、符号链接及不安全权限拒绝。

冷镜像准备前，核对整个专用 containerd 目录实际分配的磁盘块，并额外预留 25 GiB 和 1,100,000 个 inode。预留覆盖现有单镜像限制：压缩数据 4 GiB、解包数据 16 GiB、100 万目录项，以及小文件分配与元数据余量。支持不大于 4 KiB 的文件系统块；更大块大小保守拒绝，不套用不足的预留值。默认配置下冷准备需要至少 33 GiB 空闲空间和 1,200,000 个空闲 inode。

已经完整解包的镜像直接复用，不再要求整份冷准备余量，但仍核对缓存预算与基础磁盘／inode 余量。新镜像准备和缓存清理共用跨进程锁；每次实际删除后重新测量磁盘，不假设镜像声明大小就是释放空间。

这是 engine 控制路径的容量准入与保守预留，不是独立文件系统硬配额。共享磁盘上其他服务或宿主管理员的并发写入仍可能消耗空间；建议专用磁盘并配合宿主磁盘告警。目录扫描有上下文期限和数量上限，不跨挂载、不跟随链接；无法核对时拒绝新的准备。

## 回收规则

- 新拉取镜像标记 `io.monkeyai.cache=1`，记录最近使用时间。旧版留下的无标记镜像可复用并计入总占用，但不自动认领或删除。
- 压力下按最近使用时间从旧到新移除闲置的受管镜像引用；containerd 同步 GC 负责实际内容与快照引用回收。共享层或 lease 仍占用时可能不释放空间，engine 以实测余量为准。
- containerd 中任何已有容器引用的镜像，以及本地处于准备、启动、运行、停止中、删除中或失败阶段的环境镜像均受保护。只有清理已确认的 stopped／deleted 状态才能解除该状态的保护；下一次启动可以重新拉取同一固定摘要。
- 每次删除前再次核对归属、目标摘要、使用记录和活跃引用。损坏的环境日志或缓存标签会中止回收，不通过删除日志来“释放”引用。
- 回收不删除未知镜像，不执行全局 prune，不手动递归删除 containerd 内容或快照目录。无法释放足够空间时返回失败，需要管理员先清理已确认停止的环境或增加预算／磁盘空间。

失败拉取的临时内容由 containerd lease／GC 管理，释放可能有延迟；预算不足时不会将其假定为空闲空间。启动失败的环境仍保护镜像，先提交停止或删除并确认清理，再进行缓存回收。

## 运维命令

```bash
sudo /opt/monkeyai-engine/current/bin/monkeyai-engine cache inspect
sudo /opt/monkeyai-engine/current/bin/monkeyai-engine cache gc
```

inspect 只读返回预算、实际占用、镜像归属／引用及 `ready`。ready 表示当前具备下一次冷准备余量，不代表宿主整体可调度或工作负载已验收。

gc 仅在需要时回收到具备一次冷准备余量，返回删除名称和操作后的磁盘占用；没有压力时不清空全部缓存。命令最长两分钟，未释放足够空间或遇到无法核对的状态时返回非零。并发镜像操作持锁时命令返回忙，可稍后重试。新的镜像准备也会自动执行相同准入，不依赖管理员定时运行 gc。

## 自动检查边界

单元测试覆盖 LRU 顺序、未知／活跃引用保护、空间与 inode 准入、共享数据未释放时拒绝继续、失败传播及配置校验。独立 Linux ARM64 容器使用固定 containerd v2.4.2，验证真实镜像引用删除和共享内容保护，并核对磁盘扫描和取消。不替代真实镜像冷准备、磁盘压满、并发写入与宿主故障验收。
