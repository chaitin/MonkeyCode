# 扣费账本按周分区

## 数据与约束

`000029_billing_ledger_weekly` 准备新的 RANGE 分区父表，按 `occurred_at` 划分北京时间每周一 00:00 至下一周一 00:00 的左闭右开区间。分区使用周一日期命名，如 `credit_ledger_entries_20261019`。边界计算显式使用 `Asia/Shanghai`，不依赖数据库会话时区或 ISO 周所属年份。

`credit_ledger_entry_keys` 保存全局流水 ID、账户序号、幂等键、交易 ID、发生时间，以及原外键需要的用户/会话/分组标识。全局唯一性仍由 ID 主键、非空 event_key 唯一索引、账户与序号唯一索引保证；保留现有 NULL 语义。登记表与事实表一样每条流水一行，并非固定大小的小表。

原外键集中在登记表；分区事实表通过全局 ID、冲正 ID 引用登记表。BEFORE INSERT 触发器登记并严格核对身份字段，禁止同一 ID 被放到另一周或换用账户、序号、用户等身份。这样每周分区 DDL 只涉及登记表的引用，不需重复锁定账户等核心业务表。账本和登记表均禁止 UPDATE/DELETE，原金额与元数据 CHECK 约束保留。时间必须为有限值。

应用始终写父表，账户变化、流水序号、登记、事实、小时积分汇总和观察期镜像处在原业务事务中。幂等冲突不能在余额更新后被静默忽略。正常计费继续通过账户/交易锁串行化同一账户与交易的操作。

## 准备、回填与切换

升级前备份并停止旧版本后端，执行迁移 29，再部署新后端。准备迁移创建所有历史范围周分区、当前周与未来 8 周、默认分区、登记表及镜像；不在准备事务中搬运整份账本。准备涉及结构锁，仍需维护窗口。

新后端启动独立账本维护 worker，不阻塞钱包恢复和周期账户刷新。后台每批最多 1000 条，从旧账本按 `(occurred_at,id)` 游标复制；同批逐条 JSON 全字段比较通过后才推进游标。数据库 advisory transaction lock 协调所有实例，失败或进程中断可从最后已提交的批次恢复。

安装镜像时在旧表写锁保护下记录固定历史水位，后台只追赶这个有限范围；之后新增及补报记录由旧表向新父表事务内镜像，不会因持续流量而追不完。退款先到达时，会从旧账本补登记原流水身份，支持原扣费尚未进入回填批次的跨周冲正。

历史范围复制完成后，在一个语句快照内核对旧表、新表的笔数与积分总额，以及全局登记笔数。完整扫描在 DDL 锁之前执行，正常写入继续保持两份账本原子一致。只有历史游标已到水位且校验成功，才短时锁定旧表和新父表，原子切换表名与小时汇总触发器。DDL 锁等待限 2 秒，失败记录日志并重试。

切换后 `credit_ledger_entries` 为分区父表，旧表为 `credit_ledger_entries_legacy`。`billing_ledger_original_entries` 视图固定指向原表 OID，支持迁移期幂等查询回退，避免切换后误把回退查询扩散到所有周分区。

观察期保留新表到旧表的镜像；旧关系上尚未完成的语句可以向新表转发。镜像方向按触发器所在表的实际身份判断，避免切换前已建立的 Repeatable Read 旧快照误判阶段而漏写副本。触发器深度保护避免两者相互重复复制。小时汇总只在权威账本上维护一次：回填和旧副本镜像不重复记积分。

## 自动分区维护

worker 使用迁移对象所有者或具备相应角色成员资格的数据库连接，需要创建和调整分区的权限。worker 启动立即检查，此后每 24 小时检查一次，确保当前周及未来 8 周已建好。失败写结构化错误日志，每分钟重试；多实例只允许一个进行分区维护或历史回填。

默认分区接收意外的历史或远期时间，避免缺少分区导致正常事务无法落账。每日维护为其中的周补建分区并搬迁数据，不重复登记或汇总积分。搬迁在事务与父表锁保护下进行，临时关闭默认子表的不可变触发器，完成后恢复；事务失败会整体恢复触发器与数据。

ATTACH 新周分区可能扫描整个默认分区，即使积压属于其他周。为避免长时间锁表，总默认积压超过 10000 条时暂停全部自动分区 DDL 并告警，移交维护窗口处理。检测只读取至多 10001 条；取得父表锁后再次检查，防止等待锁时队列增长。后台剩余笔数监测也以 10001 条为上限，日志使用 rows_at_least。大批积压应停止写入，在维护窗口逐周显式执行：

```sql
SELECT billing_create_ledger_week('2031-01-06 00:00:00+08', 0);
```

大批迁出后应在维护窗口执行默认分区的 VACUUM (ANALYZE)，清理死元组及统计信息，再恢复自动维护。历史周不会自动删除或脱离父表。

## 观察与回滚

查询迁移进度：

```sql
SELECT phase, source_end_at, cursor_at, checked_rows, switched_at, mirror_legacy
FROM billing_ledger_partition_state;
SELECT count(*) FROM credit_ledger_entries_default;
```

确认新版本稳定、业务及账本校验通过后，可显式结束观察期，停止旧副本继续增长。此操作不删除任何历史流水：

```sql
SELECT billing_finish_ledger_observation();
```

返回 false 表示尚未切换、其他实例正持有维护锁或有活动读写，应稍后重试。结束操作采用 NOWAIT，同时锁不到两张表便整体释放，避免与新表写入后反向镜像的锁顺序形成死锁。结束观察期后，新事务不再写旧副本；已建立旧快照的长事务仍可能完成原先可见的镜像。直接写旧关系会被拒绝，应用仍应向父表写入。旧副本删除不在本次自动化范围内。

回滚前停止所有新后端 worker 及业务读写，再执行迁移工具 down 1 并部署匹配的旧版本。down 始终从当前权威分区账本补齐旧表缺失记录，不把观察期标志当作副本完整性的证明；随后恢复原结构和小时汇总触发器。补齐需要遍历分区账本，应预留维护窗口。仍有活动事务时 NOWAIT 拒绝锁表，SQL 事务整体回滚，不能强行忽略迁移错误。任何阶段 down 都保留原始流水，不删除金融事实。预留旧副本、新分区、登记及其索引的磁盘空间。

## 查询与界面

扣费明细页面默认最近 28 个自然日，默认范围写回 URL，保留显式起止日期。用户清空日期后，页面以 `range=all` 保存显式全量选择，刷新后仍保持；该标记不发送给 API。SPA 导航、浏览器前进后退和只给结束日期的历史链接不会混入默认开始日期，筛选控件同步 URL，条件变化回到第一页。结束日期转换为下一自然日零点，接口仍采用 `[from,until)`，覆盖所选日期最后一毫秒并处理夏令时。

列表、用户流水与汇总查询以直接范围谓词比较 occurred_at，NULL 上下界转换为无穷边界，允许预编译通用计划在执行时裁剪分区。接口未传日期仍查询全部有限时间记录。金额精度、分页协议及返回字段不变。

分区后的幂等检查与事件 ID 查询优先使用全局登记的唯一索引；按事件或交易查完整事实时携带登记时间，使用参数化查找裁剪到对应周。全量 COUNT、无时间模糊搜索和深 OFFSET 仍需要按实际执行计划单独评估；分区不提供这些查询的固定耗时保证。

## 验证

真实 PostgreSQL 集成测试覆盖历史回填、固定水位、周一微秒边界、跨年、未回填原扣费的冲正、全局 ID/事件/序号唯一、默认分区搬迁、多实例维护、事务回滚、切换时持续写入、小时汇总单次累计、切换后真实结算、观察期关闭及 down/up 数据保留。强制通用执行计划检查只扫描目标周。额外回归复现旧快照漏镜像及回滚丢失、观察期结束与写入反向加锁、其他周积压造成的默认分区扫描，以及旧副本缺口修复。生产页面验证涵盖默认日期、单侧历史日期的 SPA 导航与浏览器返回、筛选同步及回到第一页。
