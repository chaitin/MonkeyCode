# 模型代理超时

适用于 monkeyai 的 `/v1/chat/completions`、`/v1/responses` 和 `/v1/messages`，流式与非流式请求采用相同保护。模型代理关闭 HTTP 连接复用（`DisableKeepAlives = true`），每次请求建立新连接，请求结束后关闭。

## 上游转发

| 设置 | 时间 | 生效范围 |
| --- | --- | --- |
| TCP 建连 | 30 秒 | 直连上游或连接系统代理；来自 Go 默认 Dialer，HTTPS 代理自定义拨号使用相同值 |
| TLS 握手 | 10 秒 | 目标 HTTPS 服务及 HTTPS 系统代理 |
| 系统代理 CONNECT | 1 分钟 | Go HTTP Transport 内置的隧道建立超时，覆盖 CONNECT 请求写入和响应读取 |
| 等待响应头 | 5 分钟 | 请求体写入上游完成后开始计时，不包括响应体读取 |
| 响应体无数据 | 5 分钟 | 每次阻塞读取上游响应数据的最长等待时间；收到数据后，下一次读取重新计时 |
| 上游请求总时限 | 30 分钟 | 从 Transport 开始转发，到响应体读取完成；覆盖连接等待、DNS、建连、CONNECT、TLS、请求上传和响应读取 |
| 空闲连接回收 | 90 秒（模型代理不适用） | Transport 沿用默认值，但模型代理关闭连接复用，不保留空闲连接 |
| 等待 `100 Continue` | 1 秒 | 仅请求使用 `Expect: 100-continue` 时生效；到时直接发送请求体 |
| TCP KeepAlive 参数 | 30 秒 | TCP 保活参数，不是模型请求时限；实际探测还受操作系统默认参数影响 |

响应头、响应体和总时限定义在 `backend/internal/proxy/timeout.go`，暂未提供环境变量。其余传输参数沿用 Go 默认 Transport；HTTPS 系统代理的自定义拨号明确设置建连和握手时限。

总时限取自身限制与调用方已有 deadline 中更早的一项。客户端取消继续向上游传播。

响应体无数据计时只覆盖上游 `Read` 等待，不计入下游写入阻塞或用量解析副本的处理时间；SSE 心跳也算收到数据。持续有心跳但没有模型输出的请求最终仍受 30 分钟总时限约束。总时限会取消上游请求，不为下游 socket 写入设置 deadline。

在发送响应头之前失败，沿用代理的 HTTP 502 错误响应；响应已经开始后超时，终止响应连接，不能改写为新的 HTTP 状态。超时按失败记录，不再被误记为客户端取消。

这些保护及关闭连接复用只接入模型代理。`DirectTransport` 还供图片、视频等客户端使用，这些客户端继续使用原有连接复用策略，没有增加模型代理的 5 分钟响应头和无数据限制。系统代理的 TLS 握手修复也对其他使用 `TransportFor` 的调用生效。

## 入站 HTTP 与计费

| 设置 | 时间 | 生效范围 |
| --- | --- | --- |
| HTTP `ReadHeaderTimeout` | 5 秒 | 客户端向 monkeyai 发送请求头 |
| HTTP `IdleTimeout` | 2 分钟 | 客户端连接两次请求之间的空闲时间，不是 SSE 超时 |
| HTTP `ReadTimeout` / `WriteTimeout` | 未设置 | 没有整个请求体读取或整个响应写入的固定时限 |
| 计费结算 | 30 秒 | 上游结束后的后台结算，忽略原请求取消信号 |
| 上游 Responses 对账 | 每次 30 秒 | 由 billing 对账任务给查询操作设置 deadline |
| 服务优雅退出 | 默认 10 秒 | 服务停止时等待在途请求；可通过 `MONKEYAI_SHUTDOWN_TIMEOUT` 或 `--shutdown-timeout` 调整 |

转发总时限从 Transport 开始，不包含此前的客户端请求体读取、模型解析、会话确认和预计费。反向代理、网关或调用方自身配置的更短超时仍可先行结束连接。
