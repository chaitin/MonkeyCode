状态：已完成，自动证书、单一对外地址配置及 PR 提交前检查均通过。

采用 Nginx 官方 ACME 模块，由 admin 容器申请、续期和动态提供证书。`.env` 中的 `MONKEYAI_AUTO_TLS_ENABLED` 默认关闭，启用后使用单域名 HTTP-01 验证。管理页面、API、OAuth 和证书域名统一使用 `MONKEYAI_PUBLIC_URL`，开启自动证书时该地址必须为 HTTPS 根地址。

## 行为约定

- 空证书卷允许 Nginx 启动；证书就绪前 TLS 握手暂不可用。
- HTTP `/healthz` 表示 Nginx 已运行，不能用它证明 HTTPS 证书就绪。
- 普通 HTTP 请求跳转至配置的固定 HTTPS 根地址，ACME 模块处理验证请求。
- ACME 状态仅挂载到 admin；按 CA 目录地址的 SHA-256 隔离测试与正式环境。
- 开关关闭时恢复 HTTP 配置，不访问 CA、不清理证书数据。HTTPS 端口映射仍占用主机端口，默认 8443。
- API、OAuth、模型和 MCP 代理复用已有规则，模型和 MCP 流式请求保持关闭代理缓冲。

## 验证记录

已通过 ARM64 与 AMD64 运行镜像构建及 `nginx -t`，完整 Admin 镜像构建（包含 TypeScript 和 Vite 构建），Compose 关闭和启用配置校验，以及既有 43 项前端测试。

完整 Admin 镜像的本地 Pebble 验证已通过首次 HTTP-01 签发、HTTPS 代理、CA 暂不可用时重建复用、自动续期、订单 503 故障恢复和关闭功能保留数据，同时验证了前端构建产物、CA 隔离及续期后流式数据持续传输。测试容器、网络和数据卷已清理。

新增的续期订单 503 故障检查发现，官方 ACME 0.4.1 在订单错误分支调用 `set_error` 后未将重试时间纳入主循环调度，单域名场景可能等待 24 小时。采用校验 SHA-256 的官方源码构建模块，添加一行调度补丁并保留模块许可证。修复后的 ARM64 完整 Admin 镜像已通过全部 Pebble 检查，原订单失败用例在未延长超时时间的情况下验证通过；AMD64 运行镜像构建，以及只读根文件系统下开关开启和关闭的 `nginx -t` 检查也均通过。

单地址配置已通过后端 `go test ./...`、`go vet ./...`、SQL 结构同步检查及两份 API 契约的解析和操作标识冲突检查。登录结果和 OAuth 元数据使用统一地址，Vite 页面与全部服务代理路由已通过实际 HTTP 请求验证；Compose 开关配置、完整管理端构建和仅设置单一地址的全部 Pebble 用例均通过。本轮未配置外部 PostgreSQL/RustFS，相关数据库和存储集成测试按原有条件跳过。

本地 CA 使用 180 秒证书并提前建议续期，给临时故障重试保留有效期，避免原有短证书与随机续期窗口导致的测试时序竞争。

公网签发须在具有真实 DNS 和入口端口的部署环境另行验证；本地代理测试不代替真实 OAuth 提供方的登录联调。
