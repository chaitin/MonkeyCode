# 资源包分卷导入实现

状态：已实现并完成验证，尚未部署。分支 `feat-resource-import-volumes`。

## 范围

- 支持普通 ZIP、普通 ZIP 按字节切分的 `.zip.001`、`.zip.002` 等全部分卷，保留解压目录入口。
- 不支持原生 `.z01 + .zip` 分卷或 7z 压缩格式。文件扩展名符合要求仍须通过完整 ZIP 检查。
- 一组分卷始终作为发布者的一份完整 Agent 清单，统一预览、确认、导入；只产生一个导入批次。
- 整包仍不超过 2 GiB、展开不超过 4 GiB，不设 ZIP 条目数上限。分卷与网络传输块分别处理，最多 256 卷，每个传输块 64 MiB，末块可小于该大小。
- 保留现有宽松元数据解析、同源更新、缺失资源停用、外部引用保护、发布者锁和事务补偿。

## 管理端

沿用「资源包导入记录」页面。导入弹窗分为选择文件、上传解析、确认导入三个步骤。

1. 拖入或多选全部分卷，按编号排序；支持补充、移除、清空。检查缺卷、重复编号、混包、空文件与总大小。
2. 显示总体及每卷上传进度。暂停、网络中断或刷新后保留服务端进度，续传时重新选择原文件并核对已上传块的实际摘要，只传缺失部分。
3. 完成完整性检查后自动预览；展示各类变更汇总，可按资源类型和动作筛选。明确列出停用项并要求确认完整清单。
4. 认证归属变化或并发冲突后要求重新预览，复用已上传内容；确认阶段只提交 `upload_id`、选项、包摘要和预览摘要。
5. 列表顶部显示当前管理员的未完成任务，支持继续上传、继续确认、放弃；保留 24 小时，完成后移出未完成列表并刷新导入记录。

## 服务端

新增迁移 `000027_resource_import_uploads`，包含上传会话和传输块记录。

- 会话绑定创建管理员，每人最多保留 5 个未过期任务；其他管理员不可读取或修改。
- 传输块保存到已有对象存储，服务端检查实际大小与 SHA-256。同内容重试幂等，不同内容返回冲突。
- 上传、封存、预览、确认和取消通过会话行锁协调，避免封存后改写或导入期间删除。
- `complete` 检查传输块齐全、实际摘要、ZIP 路径及展开限制、外层文件 CRC，计算完整 ZIP 的服务端摘要，然后封存为 `ready`。
- 从对象存储逐块下载至请求级临时文件，以跨文件 `io.ReaderAt` 提供统一 ZIP 读取，不在内存或磁盘生成额外的合并 ZIP。请求结束关闭并清理临时文件。
- 生产 S3 上传先落临时文件并流式写入对象存储；整包读取也使用磁盘暂存，仍受现有资源正文内存限制约束。
- 复用 `ParseReader → ParseResources → Evaluate → Apply`，保留旧 multipart 接口，同时接受 JSON `upload_id` 请求。
- 任务有效期 24 小时，后台每分钟回收过期及取消任务的暂存对象和数据库记录；多实例使用 `SKIP LOCKED` 协调清理。对象删除失败保留记录等待重试。
- Nginx 新增上传会话路由，允许 64 MiB 二进制请求，关闭请求缓冲并使用 30 分钟代理超时。

## 接口

| 接口 | 作用 |
| --- | --- |
| `POST /api/admin/v1/resource-import-uploads` | 创建会话并声明按序排列的本地文件及大小 |
| `GET /api/admin/v1/resource-import-uploads` | 当前管理员未完成任务 |
| `GET /api/admin/v1/resource-import-uploads/{id}` | 查询已上传块及任务状态 |
| `PUT /api/admin/v1/resource-import-uploads/{id}/chunks/{index}` | 从零编号，上传逻辑 ZIP 对应的传输块 |
| `POST /api/admin/v1/resource-import-uploads/{id}/complete` | 完整性检查、计算包摘要并封存 |
| `DELETE /api/admin/v1/resource-import-uploads/{id}` | 放弃未完成任务 |
| `POST /api/admin/v1/resource-imports/preview` | 使用 upload_id 统一预览，兼容原 multipart |
| `POST /api/admin/v1/resource-imports` | 使用同一 upload_id 确认导入，兼容原 multipart |

## 外部 Expert 引用冲突

报错「资源 research 仍被其他 Expert … 引用」来自完整清单同步的停用保护：旧绑定中的资源不在本次解析结果里，但仍有启用且未删除的 Expert 使用它，而该 Expert 不属于本发布者的导入绑定。

可能原因包括新包移除或改名资源、只上传了部分资源包。处理方式为在完整包中保留资源，或解除外部 Expert 引用。本次保留该保护，错误提示增加资源类型、Expert 名称、ID 和处理建议。

同时规范化缺省和空认证归属选项，避免恢复任务时预览请求省略字段、确认请求传空对象导致错误的摘要冲突。
